Déploiement de la démo · ① le job deploy envoie la release Helm à l'API server · ② l'état voulu est enregistré dans etcd · ③ le scheduler choisit un nœud · ④ le kubelet de ce nœud démarre le pod · ⑤ le runtime dispose de l'image troc:<sha> (en démo, le job la tire du registre et la charge dans kind) · ⑥ le kubelet sonde /health : le pod n'est « prêt » qu'ensuite, et helm --wait attend ce moment · ⑦ les requêtes entrent par l'ingress, le Service les envoie aux pods prêts — le test de fumée vérifie ce chemin.
